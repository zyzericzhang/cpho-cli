| user shell → `cpho repl` argparse/Typer | Untrusted CLI argument values (workspace path, config path) cross into Python process |
| pyproject.toml install → PyPI (cmd2) | Package supply chain; cmd2 is an established package (>10 years, official author Todd Leonhardt) — accept as low risk |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.2-01-01 | Tampering | `--workspace` path traversal | mitigate | Plan 03 validates via `discover_workspace()` (resolves and filters via `resolved.relative_to(resolved_root)` per `core/workspace.py:_safe_files`). Plan 01 only forwards the Path object; no filesystem touch yet, so no exposure. |
| T-02.2-01-02 | Information Disclosure | `load_config()` reads `config.local.yml` containing API keys | accept | `core/config.py` already gitignores the file and never echoes keys. REPL never logs the resolved config. |
| T-02.2-01-03 | Denial of Service | cmd2 import time on cold start | accept | Lazy import inside `repl_command` body keeps `cpho --help` fast. cmd2 import is ~50 ms one-shot. |
| T-02.2-01-SC | Tampering (supply chain) | `cmd2>=3.5` install | mitigate | cmd2 is a well-established package (Active since 2010, used by Cisco/NetApp). Verified on PyPI: https://pypi.org/project/cmd2/. No `[ASSUMED]`/`[SUS]` flag — no human checkpoint required, but record decision: cmd2 chosen per D-01. |

(No package legitimacy gate required: cmd2 is a known, audited package per D-01 rationale.)
