# Phase 02.2: Code Review Report

**Reviewed:** 2026-05-24
**Depth:** standard
**Files Reviewed:** 23
**Status:** issues_found

## Summary

Phase 02.2 introduces a prompt_toolkit-based REPL with workspace, search, show, set,
index, and help commands plus session persistence. Code organization is clean and tests
are reasonable. No security vulnerabilities (no eval/exec, no shell injection, no secrets
in source, output_format sanitised, `_clean_text` strips raw escape byte before OCR text
hits the terminal). However several real correctness gaps deserve attention:

- `/search` with a positional query silently no-ops on a fresh session because the
  in-process `_TAG_CACHE` is empty until a workspace/index command warms it.
- `/index` in the REPL drops the user's `--config` path (the `repl` CLI flag accepts it,
  loads it into `session.config`, but never re-supplies the path on subsequent index
  builds).
- `/show <id>` reports "未找到索引" even when the index loads fine but the supplied
  problem_id is simply absent.
- `display._fit` pads truncated cells with spaces *before* the ellipsis, producing
  output like `"abc    ..."` instead of `"abc..."`.

The remaining items are quality / consistency nits.

## Critical Issues

None.

## Warnings

### WR-01: `/search <query>` silently ignored on fresh REPL (empty tag cache)

**File:** `src/cpho_cli/cli/repl/commands/search.py:73-83, 108-128`
**Issue:** `_ids_for_query` resolves a positional `query` by scanning `_TAG_CACHE[bucket]`.
The cache is only populated by `refresh_tag_cache`, which is invoked from
`do_workspace`, `do_index`, and `do_reload_index` (via `_refresh_tag_cache_if_available`).
`do_search` never calls `refresh_tag_cache` itself, nor does `ReplApp.__init__`.
So on the first `/search 力学` after launching the REPL — exactly the documented use case
in `/help` output — the positional query expands to `[]` in every bucket, `_ids_for_query`
returns `None` for all three buckets, and `query_index` is called with all filters `None`,
returning every entry in the index. The user sees "all problems" instead of "no match"
or a filtered list and has no way to know the query was discarded.
**Fix:** Warm the cache when the REPL starts (e.g., call `refresh_tag_cache(self.session)`
in `ReplApp.__init__` after `load_index_meta` succeeds) **and** call it defensively at
the top of `do_search` whenever `_TAG_CACHE["physics_model"]` and friends are all empty:
```python
async def do_search(session: SessionState, args: list[str]) -> None:
    if session.index_meta is None:
        display.error(INDEX_MISSING_MSG.format(workspace=session.workspace_path))
        return
    if not any(_TAG_CACHE[bucket] for bucket in _TAG_CACHE):
        refresh_tag_cache(session)
    ...
```

### WR-02: `/index` in REPL discards user's `--config` path

**File:** `src/cpho_cli/cli/repl/app.py:61-72`, `src/cpho_cli/cli/repl/commands/workspace.py:88-127`
**Issue:** `cpho repl --config /path/to/cfg.yml` is accepted by `repl_command`
(`src/cpho_cli/cli/app.py:256-269`) and `ReplApp.__init__` calls
`load_config(config_path)` to populate `session.config`. But the path itself is not
stored on `SessionState`, and `do_index` calls `build_index(...)` **without**
`config_path=`. `build_index` will therefore re-discover config from defaults
(workspace `config.local.yml` / env), not from the user's explicit `--config` flag.
The two index runs (preview + real) inside `do_index` may use a completely different
config than the rest of the REPL session.
**Fix:** Persist `config_path` on `SessionState` (e.g., `config_path: Path | None = None`),
populate it in `ReplApp.__init__`, and forward it to both `build_index` calls in
`do_index`:
```python
preview = build_index(
    session.workspace_path,
    config_path=session.config_path,
    provider_name=session.provider_name,
    ...
)
```

### WR-03: `/show <unknown_id>` reports "未找到索引" instead of "未找到题目"

**File:** `src/cpho_cli/cli/repl/commands/search.py:209-216`
**Issue:** The `except (IndexNotFoundError, ProblemNotIndexedError)` clause prints the
same `INDEX_MISSING_MSG` ("未找到索引，请先运行: cpho index --workspace …") for both
exception types. `ProblemNotIndexedError` only means the index exists but this
particular `problem_id` is absent (see `core/index/api.py`); telling the user to
re-run `cpho index` is misleading and may cause unnecessary, expensive re-indexing.
**Fix:** Split the handlers:
```python
try:
    entry = get_problem_entry(session.workspace_path, problem_id)
except IndexNotFoundError:
    display.error(INDEX_MISSING_MSG.format(workspace=session.workspace_path))
    return
except ProblemNotIndexedError:
    display.error(f"未找到题目: {problem_id}")
    return
```
(Also note: `get_problem_entry` in `core/index/api.py` returns `None` rather than
raising `ProblemNotIndexedError` for an unknown id, so the second handler is currently
unreachable — the `if entry is None` branch handles it. Even so, catching it together
with `IndexNotFoundError` and printing the wrong message is a latent trap if the API
behaviour ever changes.)

### WR-04: `display._fit` places padding before the ellipsis

**File:** `src/cpho_cli/cli/repl/display.py:28-33`
**Issue:** The truncation branch returns
`out + " " * max(width - _width(out + "..."), 0) + "..."`, i.e. spaces are inserted
*between* the truncated content and the `"..."` suffix. For `text="abcdefghij"` and
`width=6` this returns `"abc..."` (correct length, looks right because there's no
padding). But for any case where `_width(out + "...") < width` (which happens
whenever no character fits with the trailing `"..."` accounted for), you get e.g.
`"a  ..."` — text, spaces, ellipsis — instead of the standard `"a..."` followed by
no padding (or padding after the ellipsis to fill the column). Result: misaligned
table columns in `render_table`.
**Fix:** Move the padding to after the ellipsis (or eliminate it; tables built from
`_fit` typically rely on column-equal widths anyway):
```python
out_with_ellipsis = out + "..."
return out_with_ellipsis + " " * max(width - _width(out_with_ellipsis), 0)
```

### WR-05: `_logger()` swallows all handler errors silently and never closes files

**File:** `src/cpho_cli/cli/repl/app.py:24-30, 95-101`
**Issue:** `_logger()` lazily attaches a `FileHandler(log_path(), encoding="utf-8")`
to a module-level logger and re-uses it on every dispatched command. The handler is
never closed (no shutdown hook, no `try/finally`). For a long-lived REPL this is
acceptable, but combined with the `except Exception` in `dispatch` that uses this
logger, a failure to open the log file (permission error, disk full, parent dir
ENOENT) would itself raise inside the `except`, masking the original exception with
a totally unrelated I/O error and crashing the REPL loop.
**Fix:** Make logger setup defensive:
```python
def _logger() -> logging.Logger:
    logger = logging.getLogger("cpho_cli.repl")
    logger.setLevel(logging.ERROR)
    if not logger.handlers:
        try:
            handler = logging.FileHandler(log_path(), encoding="utf-8")
        except OSError:
            handler = logging.NullHandler()
        logger.addHandler(handler)
    return logger
```

### WR-06: `do_resume` falls back to `str(None)` when `workspace_path` is null

**File:** `src/cpho_cli/cli/repl/commands/workspace.py:156-161`
**Issue:** `payload.get("workspace_path", session.workspace_path)` only triggers the
default when the key is **missing**; if `session.json` was written with a `null`
value (e.g., earlier corruption or a future code path that allows `None`), `str(None)`
yields `"None"` and `Path("None").is_dir()` is `False`. The user gets the
"保存的工作空间不存在" warning and the previous workspace is retained — workable but
misleading. Worse, `Path("None").expanduser().resolve()` could happen to match a
real directory called `None` in cwd.
**Fix:**
```python
raw = payload.get("workspace_path")
if isinstance(raw, str):
    workspace = Path(raw).expanduser()
    if workspace.is_dir():
        session.workspace_path = workspace
        session.index_path = workspace / ".cpho" / "index.jsonl"
    else:
        display.warn("保存的工作空间不存在，保留当前工作空间。")
else:
    display.warn("session.json 未保存 workspace_path，保留当前工作空间。")
```

### IN-02: `do_show <ref>` treats numeric problem_ids as result indices

**File:** `src/cpho_cli/cli/repl/commands/search.py:198-208`
**Issue:** `ns.ref.isdigit()` switches into "1-based index of last_search_result_ids"
mode. If a workspace ever uses purely numeric problem_ids (e.g., `"42"`), the user
cannot reference them by id — they're always interpreted as a result index. Current
problem_id format (`stem-page`) seems to avoid this, but the assumption isn't
documented.
**Fix:** Either document the constraint or require explicit prefixes (`#1` for index,
bare string for id):
```python
if ns.ref.startswith("#") and ns.ref[1:].isdigit():
    ...
```

### IN-03: `CphoLexer` re-adds spaces unconditionally, producing stray tokens

**File:** `src/cpho_cli/cli/repl/completers.py:39-49`
**Issue:** `document.lines[lineno].split(" ")` returns an empty string for each
consecutive space ("a  b".split(" ") == ["a", "", "b"]) and includes a trailing empty
string when the line ends with a space. Each gets `token + " "` appended, producing
extra `class:arg " "` tokens. Only a cosmetic issue (no visible glitch on standard
terminals) but worth normalising with `split()` or filtering empties.
**Fix:**
```python
for token in document.lines[lineno].split():
    ...
```

### IN-06: `tests/test_repl_session.py` imports `conftest` as a top-level module

**Issue:** `from conftest import make_index_entry` only works because pytest happens

### IN-07: `ReplApp.__init__` silently downgrades a user-supplied bad config

**File:** `src/cpho_cli/cli/repl/app.py:61-65`
**Issue:** When `--config /path/to/bad.yml` raises `ConfigError`, the code emits a
warning **and** transparently reloads with `load_config(None)`. The user may not
notice the warning amid the banner and will proceed thinking their config is in
effect. The downstream `/index` (already discussed in WR-02) would also silently use
defaults.
**Fix:** Make the failure mode explicit — either refuse to start the REPL on a
broken explicit `--config`, or print the warning AND set a clear flag on the
session/banner so the user sees `Config: default (fallback)`:
```python
if config_path is not None:
    try:
        config = load_config(config_path)
    except ConfigError as exc:
        display.error(f"--config 无法加载: {exc}")
        raise typer.Exit(code=2)
else:
    config = load_config(None)
```
