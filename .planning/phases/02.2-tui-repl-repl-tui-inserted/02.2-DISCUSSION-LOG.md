## Superseding Spike Decision (2026-05-24)

| Area | Previous discussion result | Current active decision |
|------|----------------------------|-------------------------|
| REPL framework | cmd2 | prompt_toolkit 自建轻量框架 |
| Command model | cmd2 CommandSet | `Command` dataclass + `registry: dict[str, Command]` |
| Help/config | cmd2 argparse help + Settable | `/help` 遍历 registry；`/set` 手写白名单 |
| Output/paging | cmd2 SimpleTable/ppaged | `display.py` 自实现表格；`pydoc.pager` fallback |
| Phase 3 extension | 动态 CommandSet adapter | `SkillSpec → Command` 直接注册 |

**Reason:** spike found cmd2's CommandSet/argparse model is misaligned with the Phase 3
SkillSpec architecture, while prompt_toolkit provides better long-term completion,
lexer, and key binding surface with acceptable additional code.

## REPL 框架选型

| Option | Description | Selected |
|--------|-------------|----------|
| cmd2 | cmd 模块超集，REPL 主循环/补全/help/错误恢复开箱即用，686 stars，v3.5.1 (2026-04) | ✓ |
| prompt_toolkit 自建 | 底层输入库，需自建 REPL 循环/命令解析/help/补全，~500-800 行脚手架，10.5k stars | |
| click-repl | Click 生态 REPL 插件，一行注册但为 Click 设计（cpho 用 Typer），最后发布 2023-10 | |

**User's choice:** cmd2
**Notes:** 否决 prompt_toolkit 自建——底层能力都有但需自建 "HTTP 协议"（REPL 框架）。否决 click-repl——Click/Typer 兼容性风险和 18 个月无更新。cmd2 用 prompt_toolkit 做输入层同时提供完整 REPL 框架。

## 命令注册架构

| Option | Description | Selected |
|--------|-------------|----------|
| CommandSet 分模块 | 每组命令继承 cmd2.CommandSet，运行时 register_command_set() 动态注册 | ✓ |
| 单体 Cmd 类 | 所有 do_xxx 方法写在一个类中 | |

**User's choice:** CommandSet 分模块，按功能领域拆分：SearchCommandSet / WorkspaceCommandSet / BuiltinSkillCommandSet
**Notes:** 第三方 skill 不写 cmd2 CommandSet。数据流：第三方 skill → core SkillSpec → cli/repl SkillCommandAdapter → REPL command。cmd2 只存在 REPL 外壳层。SkillCommandAdapter 在 Phase 02.2 只预留接口和注册点，Phase 3 实现。命令统一 `/` 前缀。

## 会话状态模型

| Option | Description | Selected |
|--------|-------------|----------|
| SessionState dataclass + 少量 Settable | 独立 dataclass，cmd2 app 只持有 self.session | ✓ |
| cmd2 实例属性 | 直接挂 self.workspace、self.last_results | |
| cmd2 Settables 全部管理 | 所有状态通过 set 命令管理 | |
| 分层上下文 | workspace 级 / session 级 / command 级 | |

**User's choice:** dataclass + 少量 Settable（workspace / max_results / output_format / provider）
**Notes:** 首批字段：workspace_path / config / index_path / index_meta / last_search_query / last_search_result_ids（只存 ID）/ current_problem_id / max_results / output_format。不缓存完整 IndexEntry。Settable 不暴露内部状态。

## 输出与交互 UX

| Option | Description | Selected |
|--------|-------------|----------|
| cmd2 内置表格 | SimpleTable/BorderedTable/ppaged() + ANSI | ✓ |
| Rich 库 | Rich Table/Panel/Syntax | |
| 纯 print | 无依赖但信息密度低 | |

**User's choice:** cmd2 内置表格，不引入 Rich
**Notes:** `/show` 默认 compact + `--full` 分页完整内容。标签补全列表启动时一次性加载到内存（高频 Tab 不能动态查）。启动时预加载 index metadata（题目数/标签数/mtime）。

## workspace 确定方式

| Option | Description | Selected |
|--------|-------------|----------|
| 显式参数 > 持久化 > cwd | 三级 fallback 链 | ✓ |
| 仅显式参数 + cwd | 无持久化 last_workspace | |

**User's choice:** 三级 fallback，失效时 fallback cwd 并提示
**Notes:** banner 必须显示 workspace 和 index 状态。index 不存在时允许浏览类命令使用，`/search` 明确报错不自动触发 build_index。

## 持久化策略

| Option | Description | Selected |
|--------|-------------|----------|
| 默认历史 + 偏好，显式 /resume | 类似 Claude Code 的会话恢复机制 | ✓ |
| 仅命令历史 | cmd2 内置 | |
| 自动恢复全部状态 | 包括上次搜索上下文 | |

**User's choice:** 默认仅加载 last_workspace + 偏好，`/resume` 显式恢复会话上下文
**Notes:** /resume 校验 workspace/index 存在性和 mtime，过期则标记并提示重新搜索。不持久化完整 IndexEntry。不触发 OCR/LLM。
