# Phase 02.2: TUI REPL 骨架 - Context

**Gathered:** 2026-05-24
**Status:** Ready for planning

## Phase Boundary

Phase 02.2 交付基于 **cmd2** 的完整 REPL 骨架——主循环、斜杠命令注册系统、有状态会话、首批内置命令（`/search`、`/show`、`/workspace`、`/status`、`/config`、`/index`、`/reload-index`、`/resume`），以及第三方 skill 的动态适配接口预留。

**这不是最小 demo。** 这是一个能兼容 Phase 3 的完整 REPL 骨架——Phase 3 加 `/explain`、`/quiz` 只需添加 CommandSet 文件或 YAML skill，不改主循环。

## Implementation Decisions

### REPL 框架选型

- **D-01:** 使用 **cmd2**（v3.5+，Python 3.11+），而不是 prompt_toolkit 自建或 click-repl。
  - **理由:** cmd2 在 prompt_toolkit 之上提供了 REPL 主循环、命令注册、argparse 驱动补全/help、错误恢复、历史持久化。prompt_toolkit 自建需额外 ~500 行脚手架；click-repl 为 Click 设计（cpho 用 Typer），最后发布 2023-10 已 18 个月无更新。
  - **参考:** `docs/tui-repl-pattern.md`（REPL 交互模式参考）、`.planning/notes/tui-design-decisions.md`（D1: REPL + 斜杠命令）

### 命令注册架构

- **D-02:** 内置命令按功能领域拆分为 **cmd2 CommandSet 模块**，不是单体 Cmd 类：
  - `SearchCommandSet`: `/search`、`/show`、`/related`
  - `WorkspaceCommandSet`: `/workspace`、`/status`、`/config`、`/index`、`/reload-index`、`/resume`
  - `BuiltinSkillCommandSet`: `/explain`、`/quiz`（Phase 3 实现，Phase 02.2 预留注册点）

- **D-03:** **第三方 skill 不写 cmd2 CommandSet。** 第三方 skill 是 YAML 或 Python SkillBase，由 core skill loader 发现，cli/repl 层的 `SkillCommandAdapter` 动态包装成 REPL 命令。数据流：`第三方 skill → core SkillSpec → cli/repl SkillCommandAdapter → REPL command`。cmd2 只存在于 REPL 外壳层，不侵入 core。

- **D-04:** SkillCommandAdapter 在 Phase 02.2 **只预留接口和注册点**，不完整实现动态 skill 命令生成。等 Phase 3 的 SkillSpec、YAML inputs、runner 和补全声明稳定后再实现。`/run <skill_name>` 可作为 debug/fallback 命令。

- **D-05:** 所有 REPL 命令统一使用 **`/` 前缀**，不做自然语言意图推断。命令边界清晰，补全、help、测试和错误处理简单。如需自然语言入口，未来可加显式 `/ask` 或 `/chat` 命令。

- **D-06:** 命令帮助文本从 **cmd2 argparse 自动生成**（Single Source of Truth）。不维护独立的 help 文本映射。

### 目录结构

- **D-07:** REPL 代码全部放在 `src/cpho_cli/cli/repl/`，不放入 `core/`：
  ```
  src/cpho_cli/cli/repl/
    app.py              # cmd2.Cmd 子类，REPL 入口
    session.py          # SessionState dataclass
    registry.py         # CommandSet 注册 + 动态 skill 适配注册点
    commands/
      search.py         # SearchCommandSet
      workspace.py      # WorkspaceCommandSet
      builtin_skills.py # BuiltinSkillCommandSet（Phase 3 填充）
    adapters/
      skill_command.py  # SkillCommandAdapter 接口预留
  ```
  **core 目录不引入 cmd2 依赖**，保持纯业务逻辑，可被 Typer CLI、REPL、测试、notebook、GUI 共同调用。

### 会话状态模型

- **D-08:** 会话状态使用独立 **`SessionState` dataclass**。cmd2 app 实例只持有 `self.session: SessionState`，不直接挂业务属性（`self.workspace`、`self.last_results`）。

- **D-09:** SessionState 首批字段（只存引用，不存完整对象）：
  - `workspace_path: Path` — 当前工作空间
  - `config: Config` — 当前配置
  - `index_path: Path | None` — 索引文件路径
  - `index_meta: IndexMeta | None` — 轻量元数据（题目数、标签数、index_mtime/index_version），用于 banner 和 /status
  - `last_search_query: str | None` — 上一次搜索词
  - `last_search_result_ids: list[str]` — 搜索结果 problem_id 列表（只存 ID）
  - `current_problem_id: str | None` — 当前题目，供 Phase 3 /explain、/quiz 默认使用
  - `max_results: int` — 搜索最多显示数量
  - `output_format: str` — compact/full

- **D-10:** Settable 只暴露用户可安全修改的配置项：`workspace`、`max_results`、`output_format`、`provider`。不暴露内部状态（`last_search_result_ids`、`current_problem_id`、`index_meta`）。

- **D-11:** `/search` 和 `/show` 通过 **core index API 按需读取完整数据**（`query_index`、`get_problem_entry`）。不缓存完整 IndexEntry 列表在内存，保证 index 更新后不使用过期对象。

### 输出与交互 UX

- **D-12:** 输出使用 **cmd2 内置表格/分页/ANSI**，不引入 Rich 依赖。`/search` 结果用 `SimpleTable`/`BorderedTable`，`/show` 用 ANSI 分区块展示。

- **D-13:** `/show` 默认 **compact**（OCR 前若干字符 + 标签列表 + 来源试卷 + 页码 + problem_id），提示可用 `--full` 查看完整文本。`/show --full` 使用 cmd2 `ppaged()` 分页显示完整 OCR 文本、标签、来源、索引时间。

- **D-14:** 标签补全列表 **REPL 启动时一次性加载到内存**（从 index canonical vocabulary 读取 tag ID + display name），不每次 Tab 动态查询。workspace 切换、index 文件 mtime 变化、或用户手动 `/reload-index` 时刷新。标签量通常很小，内存缓存避免高频 Tab 卡顿。

- **D-15:** 启动时预加载 **轻量 index metadata**（题目数、标签数、index_mtime/index_version）用于 banner 和 `/status`。完整 IndexEntry/OCR 文本由各命令按需读取。

### 启动与 workspace

- **D-16:** workspace 确定优先级：**显式参数** `cpho repl --workspace /path` > **持久化的 last_workspace** > **当前 cwd**。如果恢复的 last_workspace 不存在，fallback 到 cwd 并提示用户可用 `/workspace` 切换。

- **D-17:** 启动 banner 必须显示：workspace 路径、index 状态（题数/标签数 或 "未建立"）、LLM provider。避免用户误操作错误题库。

- **D-18:** REPL 启动时 **workspace 存在但 index 不存在时不退出**。允许 `/help`、`/config`、`/workspace`、`/status` 等浏览/配置类命令正常使用。依赖 index 的命令（`/search`、`/show`）执行时给出明确提示和可复制命令 `cpho index --workspace <path>`。

### 错误处理与 index 交互

- **D-19:** `/search` 在 index 不存在时**明确报错** "未找到索引，请先运行 cpho index"，给出可复制命令。**不自动触发 build_index**（OCR + LLM 有耗时和 token 成本），**不返回空结果**（会误导用户以为题库无匹配题）。

- **D-20:** `/index` 命令存在，**必须先 `--dry-run` 预览**（待处理文件数、是否会触发 OCR/LLM、估计成本范围），正式执行需二次确认。`/index` 调用 **core `build_index` API**，不 shell 出去执行 CLI 字符串。

- **D-21:** 命令异常由 **cmd2 内置异常捕获框架**处理，不退出 REPL。`Ctrl+C` 中断当前命令返回 prompt，不退出 REPL（cmd2 默认行为）。LLM 调用失败复用 `core/llm.py` 的重试机制。

### 持久化

- **D-22:** 默认启动**仅加载 last_workspace 和用户偏好**（max_results、output_format），不自动恢复上次搜索上下文。

- **D-23:** **`/resume` 命令显式触发会话恢复**（类 Claude Code）。恢复内容：last_workspace、last_search_query、last_search_result_ids、current_problem_id、session metadata。恢复时**校验 workspace 和 index 是否仍存在**，检查 index mtime/version。如果 index 已变化，恢复 workspace 和 history，但丢弃/标记过期的 search/current_problem 上下文，提示用户重新 `/search`。

- **D-24:** **不持久化完整 IndexEntry 对象**，只持久化 problem_id 引用和轻量 metadata。`/resume` 不触发 OCR/LLM/index rebuild。

- **D-25:** 命令历史持久化使用 **cmd2 内置机制**（压缩 JSON 文件）。

### Skill 补全声明（Phase 3 预留）

- **D-26:** Phase 3 的 SkillSpec 应声明 `completions` 字段或 input type（如 `problem_ref`、`tag`、`file_path`、`enum`、`free_text`）。SkillCommandAdapter 据此生成 cmd2 补全逻辑。Phase 02.2 定义最小接口，不完整实现所有补全类型。

## Existing Code Insights

### Reusable Assets
- `core/index/api.py` 的 `query_index`/`get_problem_entry`/`find_related_problems` — REPL 命令的数据源，不重写搜索逻辑
- `core/workspace.py` 的 `discover_workspace` — workspace 验证和发现
- `core/config.py` 的配置加载 — REPL 启动时复用
- `models/index.py` 的 `IndexEntry` — `/show` 展示的数据模型

### Established Patterns
- **芯-壳分离**: REPL 在 `cli/repl/` 层，只调 `core/` API，不包含业务逻辑
- **中文 UX**: 所有用户界面默认中文
- **Pydantic 模型**: SessionState、IndexMeta 使用 Pydantic/dataclass
- **YAML 配置驱动**: 配置通过 `config.local.yml` 控制

### Integration Points
- **Typer CLI** → REPL 是平行入口，不替换 Typer CLI
- **core index API** → REPL 查询的唯一数据源
- **core skill loader** → Phase 3 SkillCommandAdapter 的输入（Phase 02.2 预留接口）
- **Phase 3 /explain、/quiz** → 通过 BuiltinSkillCommandSet 注册（Phase 02.2 预留注册点）

## Specific Ideas

- REPL 启动 banner 格式参考 `docs/tui-repl-pattern.md` 的可视化示例（双线框、workspace + index 状态 + LLM provider）
- `/search` 结果表格格式：ID / 题目摘要 / 标签 / 来源试卷，类似 `docs/tui-repl-pattern.md` 中的示例
- `/show` 展示格式：题目编号 + 来源文件 + OCR 文本分块 + 标签列表 + 索引日期
- `/resume` 行为参考 Claude Code 的会话恢复——显示恢复内容摘要，校验后应用
- `/index --dry-run` 输出类似 `cpho index --dry-run` 的统计预览
