<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local file -> remote OpenRouter API | User problem PDFs/images may be uploaded when multimodal routing is enabled and supported. |
| OpenRouter metadata -> routing decision | Remote metadata can be unavailable or incomplete; routing must fail closed to OCR text. |
| OCR text/file names -> prompt payload | File names and OCR text are untrusted content entering LLM messages. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.3-17 | Information Disclosure | solve multimodal file upload | mitigate | Only send file/image blocks when model capabilities support the required modality; text-only models use local OCR fallback. |
| T-02.3-18 | Tampering | OpenRouter capability metadata | mitigate | Treat missing/failed metadata as text-only; do not force multimodal payloads on uncertain support. |
| T-02.3-19 | Information Disclosure | provider/capability errors | mitigate | Redact API keys using existing redact_secrets pattern in all metadata/provider failures. |
| T-02.3-20 | Denial of Service | large/unsupported files | mitigate | Recognize only D-21 suffixes and keep downstream model file limits as provider errors with redacted messages; do not add PDF-to-image expansion. |
| T-02.3-SC | Tampering | npm/pip/cargo installs | accept | No package installation is planned. |
</threat_model>
