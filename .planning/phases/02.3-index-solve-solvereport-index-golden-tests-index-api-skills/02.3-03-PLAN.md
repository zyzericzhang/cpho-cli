<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI args -> JSONL index | User/skill-supplied problem IDs, tags, skill names, and reasoning enter local persisted data. |
| Vocabulary files -> tag classification | Workspace/private vocabulary files determine canonical vs unverified classification. |
| Rebuild flags -> existing index data | --force and --force-all control whether skill-written user_tags are retained or cleared. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.3-07 | Tampering | core/index/api.py problem_id | mitigate | Reuse PROBLEM_ID_PATTERN validation and raise ProblemNotIndexedError for absent IDs. |
| T-02.3-08 | Repudiation | UserTagEntry provenance | mitigate | Every add/update requires skill_name and reasoning and writes timestamp; remove operations are tested but do not fabricate provenance. |
| T-02.3-09 | Tampering | user tag classification | mitigate | Classify against merged vocabulary and persist unmatched tags as unverified rather than silently inserting canonical IDs. |
| T-02.3-10 | Accidental data deletion | build_index --force-all | mitigate | --force preserves user_tags; only explicit --force-all clears them, with tests covering both flags. |
| T-02.3-SC | Tampering | npm/pip/cargo installs | accept | No package installation is planned. |
</threat_model>
