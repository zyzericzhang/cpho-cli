<objective>
Add hierarchical topic classification as a second indexing dimension alongside flat tags. Topics form a tree (each problem gets exactly one topic_path), enabling browsing by subject area and exam composition by topic+tag intersection.

Purpose: Tags answer "what knowledge does this problem use?" Topics answer "what subject area is this?" Together they enable the primary retrieval use case: find all orbital mechanics problems that use angular momentum conservation.

Output: TopicNode model, builtin topic taxonomy YAML, LLM topic assignment pipeline, topic query API, CLI commands (cpho topic list, cpho topic browse, cpho compose), and integration hooks for build_index.
</objective>

1. Load builtin: `_load_topic_yaml(_builtin_topic_path(), optional=False)`.
2. Load workspace: `_load_topic_yaml(workspace_root / ".cpho" / "topics" / "workspace_topics.yml", optional=True)`.
3. Load private: `_load_topic_yaml(workspace_root / ".cpho" / "topics" / "private_topics.yml", optional=True)`.
4. Merge: builtin -> workspace -> private (last wins on id collision).
5. Compute version string: `f"{base.version}+bt-{sha8}+ws-{ws_sha8 or 'none'}+pv-{pv_sha8 or 'none'}"`, matching vocabulary.py pattern.
6. Return the merged TopicTaxonomy.
