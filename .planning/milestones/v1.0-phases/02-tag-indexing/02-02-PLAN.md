Output: `src/cpho_cli/core/index/hashing.py` + `tests/test_index_hashing.py`. No I/O on the index itself (storage.py from 02-01 handles that). No CLI surface.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem → process | sha256_file reads arbitrary problem/answer files; pymupdf already handles malformed PDFs upstream, hashing is read-only bytes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02 | Tampering | A user could replace a problem PDF with malicious content between hashing and OCR | accept | Single-user local CLI; no TOCTOU adversary. Hash is read once at fingerprint time; OCR re-reads but that mismatch only causes a stale fingerprint, not security harm. |
| T-02-02b | Repudiation | None — no audit log requirement for hashing | accept | Not applicable; index trace lives at Plan 02-04. |
| T-02-02c | Information Disclosure | sha256 of file content is not sensitive | accept | sha256 is one-way; we never log raw file bytes. |
</threat_model>
