# Phase 02.1: Paper Splitting — Specification

**Created:** 2026-05-24
**Ambiguity score:** 0.15 (gate: ≤ 0.20)
**Requirements:** 6 locked

## Goal

将多题试卷 PDF（如 `模拟试卷七.pdf` + `模拟试卷七解析.pdf`）按题号拆分为独立的 `ProblemEntry` 条目，使 Phase 1 solve 与 Phase 2 index 的下游消费单位从「文件」升级为「题目」，修复真实工作空间（一份卷含多道大题）与现有「1 文件 = 1 题」数据模型之间的形状错配。

## Background

当前数据模型与工作空间形状不匹配：

- `src/cpho_cli/models/documents.py:23-44` 定义 `ProblemFile(path)` / `ProblemAnswerPair(problem, answer)`，每个 PDF 文件被视为一道题。
- `src/cpho_cli/core/workspace.py:53-78` 的 `discover_workspace()` 按 stem 名匹配题目-答案配对，无法表达「一份 PDF 内多道大题」。
- `src/cpho_cli/models/index.py:121-138` 的 `IndexEntry.problem_path` 同样指向整份文件，导致 Phase 2 索引把一份卷打成一个标签集合。
- 真实工作空间 `~/Desktop/物理竞赛资料` 抽样（`杂题/`、`2024机构卷/`、`24套模拟试题/` 等）显示主流形态是「试卷 PDF（多题）+ 解析 PDF（多题）」，而非单题 PDF。

后续 Phase 3 Explanation/Quiz 与 Phase 4 组卷/对比都建立在 `IndexEntry` 上，本错配必须在 Phase 3 前修复，否则下游 skill 输出粒度也会被锁死在「整卷」。

## Requirements

1. **PaperFile 与 ProblemEntry 数据模型**: 引入分层数据结构区分「试卷文件」与「题目条目」。
   - Current: 仅有 `ProblemFile(path)`，无题号/页范围/内文字段
   - Target: 新增 `PaperFile(path, paper_kind, total_pages)` 与 `ProblemEntry(problem_id, paper_path, problem_number, problem_page_range, problem_text, answer_paper_path?, answer_page_range?, answer_text?, split_method, split_confidence)`，作为 StrictModel 进入 `cpho_cli/models/documents.py`
   - Acceptance: `pytest` 单测验证：构造 `ProblemEntry` 必填字段缺失会抛 ValidationError；`problem_id` 在同一 `paper_path` 内唯一且可复现（`paper_sha256:NN` 形式）；`problem_page_range` 为 `(start_inclusive, end_inclusive)` 1-indexed 元组

2. **规则切分器**: 基于 OCR 文本与页码的确定性规则切分。
   - Current: 不存在切分逻辑
   - Target: `split_paper_by_rules(paper_ocr, answer_ocr?) -> SplitOutcome` 在 `cpho_cli/core/splitting/rules.py`，识别中文/英文题号标记（`第N题`、`(N)`、`N.`、`Problem N`、`题N`），输出题号列表 + 每题页范围（起始页 = 首次出现页，终止页 = 下一题首次出现页 − 1，或 paper 末页）
   - Acceptance: 给定 `tests/fixtures/paper_with_5_problems.json`（mock OCR 文本）输入，输出 5 个 `ProblemEntry`，题号 1–5，页范围连续无重叠，覆盖全部页

3. **LLM 兜底切分器**: 规则不可信时调用 LLM 复核。
   - Current: 无
   - Target: `split_paper_with_llm(paper_ocr, answer_ocr?) -> SplitOutcome` 在 `cpho_cli/core/splitting/llm.py`，复用 `core/llm.py` provider 接口，Jinja2 prompt 模板版本化（`split_prompt_version` 进入 `SemanticFingerprint`），返回结构化 JSON（题号、页范围、答案题号映射）
   - Acceptance: 触发条件单测：当规则切分检出题号非连续 / 题数 = 0 / 题号重复 / 答案题号与题目题号集合不一致时，`split_paper()` 编排器调用 LLM 路径

4. **切分编排器与 split 阶段**: 整合规则优先 + LLM 兜底，并把答案卷一并切分配对。
   - Current: 无 split 阶段；`discover_workspace()` 直接产 `ProblemAnswerPair`
   - Target: 新增 `cpho_cli/core/splitting/__init__.py:split_paper(paper_ocr, answer_ocr?)`，先跑规则、按 R3 触发条件回退 LLM；答案卷按相同流程切分，按题号与题目 ProblemEntry 逐一配对，未匹配题号挂在 `SplitOutcome.unmatched_answers`；`discover_workspace()` 改产 `list[PaperFile]` + `list[PaperAnswerPair]`（试卷级配对），由 `split_paper()` 把 pair 展开为 `list[ProblemEntry]`
   - Acceptance: `tests/test_splitting_integration.py` 用一份真实 fixture 卷验证：题数与人工标注一致，答案题号配对率 ≥ 80%（未配对的进 `unmatched_answers`，不报错）

5. **CLI 与索引集成**: `cpho index` 消费 ProblemEntry 而非 PaperFile。
   - Current: `cpho index` 把每个 PDF 文件作为一个 `IndexEntry`
   - Target: `cpho index` 在 OCR → tagging 之前插入 split 阶段，`IndexEntry.problem_id` = ProblemEntry.problem_id，`IndexEntry.problem_path` 改为指向 `PaperFile.path` 并新增 `problem_page_range` 字段；`IndexRunStats` 新增 `papers_split: int`、`problems_extracted: int`、`split_method_rules: int`、`split_method_llm: int` 字段；不提供旧索引迁移脚本，重跑 `cpho index` 触发全量重建
   - Acceptance: 在 sample workspace 跑 `cpho index`，输出 JSONL 中每个 IndexEntry 对应一道题（不是一份卷），`IndexRunStats.problems_extracted` > `papers_split`

6. **验收 golden 卷**: 锁定一份手工标注的回归门槛卷。
   - Current: 无切分回归测试集
   - Target: `golden_tests/splitting/` 下放入 1 份真实 IPhO 风格多题 PDF + 手工 JSON 标注（题号、页范围、答案题号映射），并在 `tests/test_splitting_golden.py` 中作为 pytest 用例运行
   - Acceptance: `pytest tests/test_splitting_golden.py` 在 CI 中 PASS：题号集合精确匹配、页范围 ±1 页内匹配、答案配对率 100%

## Boundaries

**In scope:**
- 新增 `PaperFile` / `ProblemEntry` Pydantic StrictModel
- 规则切分器（正则 + 页号定位）
- LLM 切分器与 prompt 模板（versioned）
- 切分编排器 `split_paper()`（rules → LLM 兜底）
- 答案卷同步切分 + 题号配对
- `discover_workspace()` 升级为 `PaperFile`-based
- `cpho index` 流程接入 split 阶段
- `IndexEntry` schema 增量改动（`problem_path` 仍是文件路径 + 新增 `problem_page_range`）
- `IndexRunStats` 新增切分统计字段
- 1 份 golden splitting fixture + pytest 集成

**Out of scope:**
- 物理切分出子 PDF 文件 — 决议为「虚拟 ProblemEntry」，不在磁盘产出派生 PDF
- 旧 IndexEntry 迁移脚本 — 决议为「不迁移，重跑 `cpho index` 全量重建」
- 单文件单题路径的并行双轨保留 — 单题情况下 `split_paper()` 输出 1 个 ProblemEntry 即可，无需双轨
- 题中小问（如 `(1)(2)(3)`）的进一步细分 — 本阶段切到「大题」粒度即止，小问留给后续 skill 自行解析
- 切分结果的人工修订 UI / TUI / 编辑命令 — 错切只能改 prompt/规则后重跑
- `cpho solve` 对 ProblemEntry 的消费改造 — 留给后续小补丁（本阶段确保 ProblemEntry → solve 输入的转换函数存在即可，不改 solve.py）
- 图片型工作空间（`.png`/`.jpg` 单图扫描题）的切分 — 仍走单题路径，不进 split

## Constraints

- 必须使用 OCR 后的纯文本驱动切分，不直接解析 PDF 矢量层（与 RapidOCR 抽象保持一致，复用 `CachedOCRProvider`）
- LLM 调用必须经 `core/llm.py` provider 接口，不绕过；prompt 模板版本入 `SemanticFingerprint.split_prompt_version`，prompt 变更触发缓存失效
- `ProblemEntry.problem_id` 必须可复现（同一 `paper_sha256` + 同一 split prompt version 多次跑结果一致），便于 Phase 2 增量索引
- 规则切分必须在 < 100ms/卷 完成（无 LLM 调用）；LLM 兜底接受 < 30s/卷
- 不引入新的二进制依赖（pypdf/pikepdf 已在 deps 中可用即可，不需则不引）
