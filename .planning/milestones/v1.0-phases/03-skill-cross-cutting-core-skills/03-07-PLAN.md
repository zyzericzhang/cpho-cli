<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| REPL command args -> skill services | User command arguments select problem ids, tones, and confirmation behavior. |
| confirmed findings/tags -> index | Accepted Solve/Explain items cross into persisted index user_tags. |
| skill output -> follow-up provider | Completed skill markdown may become follow-up context. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-07-01 | Tampering | index writeback | mitigate | Resolve problem ids through existing index API and call `add_problem_tags`; never mutate machine tag buckets directly. |
| T-03-07-02 | Repudiation | confirmation UI | mitigate | Store `skill_name` and reasoning/provenance snippets through `UserTagEntry`. |
| T-03-07-03 | Information Disclosure | follow-up context | mitigate | Follow-up is entered only after a successful skill run and uses the current skill context, not full session history. |
</threat_model>
