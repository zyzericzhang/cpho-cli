# Phase 02.2: TUI REPL 骨架 - Context

**Gathered:** 2026-05-24
**Revised:** 2026-05-24 — REPL 框架由 cmd2 改为 prompt_toolkit 自建（依据 spike `.planning/spikes/02.2-repl-framework-comparison/COMPARISON.md`）
**Status:** Ready for planning

## Phase Boundary

Phase 02.2 交付基于 **prompt_toolkit 自建轻量框架**的完整 REPL 骨架——主循环、斜杠命令注册系统、有状态会话、首批内置命令（`/search`、`/show`、`/workspace`、`/status`、`/config`、`/index`、`/reload-index`、`/resume`、`/help`、`/set`），以及第三方 skill 的动态适配接口预留。

**这不是最小 demo。** 这是一个能兼容 Phase 3 的完整 REPL 骨架——Phase 3 加 `/explain`、`/quiz` 只需 `registry[name] = Command(...)` 一行，不改主循环。

## Implementation Decisions

### REPL 框架选型

- **D-01:** 使用 **prompt_toolkit 自建轻量框架**（prompt_toolkit v3.0.50+，Python 3.11+），而不是 cmd2 或 click-repl。
  - **核心抽象:** `Command` dataclass + `registry: dict[str, Command]`。主循环 = `PromptSession + while: prompt_async + shlex + registry.get`。
  - **理由（依据 spike COMPARISON.md）:**
    1. **生态碾压** — prompt_toolkit ~12M 周下载（IPython/pgcli/AWS CLI v2/Azure CLI 使用），cmd2 ~3.5k 周下载、单维护者（bus factor = 1）。
    2. **架构同构** — `Command` dataclass 与 Phase 3 的 `SkillSpec` 天然对齐，`SkillCommandAdapter` 就是 `registry[f"/{skill.name}"] = Command(...)` 一行；cmd2 的 CommandSet/argparse 模型与 SkillSpec 存在阻抗失配。
    3. **UX 上限** — prompt_toolkit 原生支持语法高亮（`Lexer`）、上下文感知补全（`Completer.get_completions` 接收 document 状态）、自定义 key binding（Ctrl+R/Ctrl+O 等 Claude Code 风格快捷键），cmd2 全部做不到。
    4. **长期风险低** — prompt_toolkit 是社区维护、Pallets/Pocoo 生态量级；cmd2 单维护者+依赖 pyperclip（多年未更新）。
    5. **代码量差距小** — 完整 Phase 02.2 净差额约 50–100 行；其中约一半（帮助/表格/分页/Settable）是写一次就不再动的 UI 代码。
  - **代价（已接受）:** Phase 02.2 初期多投入 0.5–1 天写脚手架（Command/registry/主循环/Completer/display），但脚手架在 Phase 3/4/5 持续摊销。
  - **参考:** `.planning/spikes/02.2-repl-framework-comparison/COMPARISON.md`、`docs/tui-repl-pattern.md`、`.planning/notes/tui-design-decisions.md`

### 命令注册架构

- **D-02:** 命令注册采用 **`Command` dataclass + 全局 `registry: dict[str, Command]`** 模型，handler 是普通函数（不是类方法）。内置命令按功能领域拆分到 `commands/` 子模块，每个模块 export 一个 `register(registry)` 函数：
  - `commands/search.py`: `/search`、`/show`（`/related` 延后到 Phase 4）
  - `commands/workspace.py`: `/workspace`、`/status`、`/config`、`/index`、`/reload-index`、`/resume`
  - `commands/builtin_skills.py`: `/explain`、`/quiz`（Phase 3 实现，Phase 02.2 预留 `register()` 空壳与注册点）
  - `commands/help_cmd.py`: `/help`（遍历 registry 输出中文分组帮助）
  - `commands/set_cmd.py`: `/set`（替代 cmd2 Settable，仅暴露 D-10 列出的字段）

- **D-03:** **第三方 skill 不写 Command。** 第三方 skill 是 YAML 或 Python SkillBase，由 core skill loader 发现，cli/repl 层的 `SkillCommandAdapter` 把 `SkillSpec` 映射为 `Command` dataclass 后注册。数据流：`第三方 skill → core SkillSpec → cli/repl SkillCommandAdapter → registry[f"/{name}"] = Command(...)`。prompt_toolkit 只存在于 REPL 外壳层，不侵入 core。

- **D-04:** SkillCommandAdapter 在 Phase 02.2 **只预留接口（函数签名 + docstring）和注册点**，不完整实现动态 skill 命令生成。等 Phase 3 的 SkillSpec、YAML inputs、runner 和补全声明稳定后再实现。`/run <skill_name> [args...]` 在 Phase 02.2 作为 debug/fallback 命令，直接调用 core skill loader。

- **D-05:** 所有 REPL 命令统一使用 **`/` 前缀**，不做自然语言意图推断。命令边界清晰，补全、help、测试和错误处理简单。如需自然语言入口，未来可加显式 `/ask` 或 `/chat` 命令。

- **D-06:** 命令帮助由 `/help` 命令遍历 `registry` 生成，**`Command.help` / `Command.usage` 字段是 Single Source of Truth**。命令内部可用 argparse 解析参数，但**用户面对的帮助文本来自 dataclass 字段**（中文、分组、带示例），不暴露 argparse 的英文默认输出。`/help <command>` 输出单个命令的 usage + 详细说明 + 示例。

### 目录结构

- **D-07:** REPL 代码全部放在 `src/cpho_cli/cli/repl/`，不放入 `core/`：
  ```
  src/cpho_cli/cli/repl/
    __init__.py
    app.py              # ReplApp：PromptSession 主循环 + 异常处理 + banner
    commands.py         # Command dataclass + 全局 registry: dict[str, Command]
    completers.py       # CphoCompleter：根据 registry + Command.completer 路由
    session.py          # SessionState dataclass + IndexMeta 模型
    display.py          # 表格 / 分页 / ANSI 颜色工具（无 Rich / 无 tabulate）
    persistence.py      # last_workspace / session snapshot 读写（D-22..D-24）
    commands/
      __init__.py
      search.py         # /search, /show handler + register()
      workspace.py      # /workspace, /status, /config, /index, /reload-index, /resume handler
      builtin_skills.py # Phase 3 stub（register() 空函数，预留注册点）
      help_cmd.py       # /help handler
      set_cmd.py        # /set handler（替代 cmd2 Settable）
      run_debug.py      # /run <skill_name> debug 命令（D-04 fallback）
    adapters/
      __init__.py
      skill_command.py  # SkillCommandAdapter 接口预留（Phase 3 实装）
  ```
  **core 目录不引入 prompt_toolkit 依赖**（仅 `cli/repl/` 可 import prompt_toolkit），保持纯业务逻辑，可被 Typer CLI、REPL、测试、notebook、GUI 共同调用。

### 会话状态模型

- **D-08:** 会话状态使用独立 **`SessionState` dataclass**。`ReplApp` 实例只持有 `self.session: SessionState`，不直接挂业务属性（`self.workspace`、`self.last_results`）。所有 handler 接收 `session` 作为参数，避免隐式依赖 app 实例。

- **D-09:** SessionState 首批字段（只存引用，不存完整对象）：
  - `workspace_path: Path` — 当前工作空间
  - `config: Config` — 当前配置
  - `index_path: Path | None` — 索引文件路径
  - `index_meta: IndexMeta | None` — 轻量元数据（题目数、标签数、index_mtime/index_version），用于 banner 和 /status
  - `last_search_query: str | None` — 上一次搜索词
  - `last_search_result_ids: list[str]` — 搜索结果 problem_id 列表（只存 ID）
  - `current_problem_id: str | None` — 当前题目，供 Phase 3 /explain、/quiz 默认使用
  - `max_results: int` — 搜索最多显示数量
  - `output_format: str` — compact/full

- **D-10:** `/set` 命令只暴露用户可安全修改的配置项：`workspace`、`max_results`、`output_format`、`provider`。不暴露内部状态（`last_search_result_ids`、`current_problem_id`、`index_meta`）。`/set` 不带参数列出当前值，`/set <key>` 显示当前值，`/set <key> <value>` 修改并验证。注册到 registry 的 Command 通过 `completer` 字段提供 key 名称补全。

- **D-11:** `/search` 和 `/show` 通过 **core index API 按需读取完整数据**（`query_index`、`get_problem_entry`）。不缓存完整 IndexEntry 列表在内存，保证 index 更新后不使用过期对象。

### 输出与交互 UX

- **D-12:** 输出在 `display.py` 自实现：
  - **表格** — 简单 ASCII / Unicode 对齐表格，纯 stdlib（`str.ljust`、`wcwidth` 算列宽以支持中文）。不引入 Rich / tabulate。
  - **ANSI 颜色** — 直接用 `\033[...m` 转义或 `prompt_toolkit.formatted_text` 的 `FormattedText`。
  - **语法高亮（输入行）** — 实现 `CphoLexer(Lexer)`：`/command` 蓝色、`--flag` 黄色、`参数` 绿色。这是 prompt_toolkit 相对 cmd2 的核心 UX 增益。
  - `/search` 结果用 `display.render_table()`，`/show` 用分区块 ANSI 展示。

- **D-13:** `/show` 默认 **compact**（OCR 前若干字符 + 标签列表 + 来源试卷 + 页码 + problem_id），提示可用 `--full` 查看完整文本。`/show --full` 通过 `display.pager(text)` 分页显示完整 OCR 文本、标签、来源、索引时间。分页实现优先用 stdlib `pydoc.pager`（无外部依赖），fallback 到 `print` 直出。

- **D-14:** 标签补全列表 **REPL 启动时一次性加载到内存**（从 index canonical vocabulary 读取 tag ID + display name），不每次 Tab 动态查询。workspace 切换、index 文件 mtime 变化、或用户手动 `/reload-index` 时刷新。`CphoCompleter` 读取该缓存生成 `Completion` 对象。标签量通常很小，内存缓存避免高频 Tab 卡顿。

- **D-15:** 启动时预加载 **轻量 index metadata**（题目数、标签数、index_mtime/index_version）用于 banner 和 `/status`。`IndexMeta` 是独立 dataclass（不是完整 IndexEntry 列表）。完整 IndexEntry/OCR 文本由各命令按需读取。

### 启动与 workspace

- **D-16:** workspace 确定优先级：**显式参数** `cpho repl --workspace /path` > **持久化的 last_workspace** > **当前 cwd**。如果恢复的 last_workspace 不存在，fallback 到 cwd 并提示用户可用 `/workspace` 切换。

- **D-17:** 启动 banner 必须显示：workspace 路径、index 状态（题数/标签数 或 "未建立"）、LLM provider。避免用户误操作错误题库。

- **D-18:** REPL 启动时 **workspace 存在但 index 不存在时不退出**。允许 `/help`、`/config`、`/workspace`、`/status` 等浏览/配置类命令正常使用。依赖 index 的命令（`/search`、`/show`）执行时给出明确提示和可复制命令 `cpho index --workspace <path>`。

### 错误处理与 index 交互

- **D-19:** `/search` 在 index 不存在时**明确报错** "未找到索引，请先运行 cpho index"，给出可复制命令。**不自动触发 build_index**（OCR + LLM 有耗时和 token 成本），**不返回空结果**（会误导用户以为题库无匹配题）。

- **D-20:** `/index` 命令存在，**必须先 `--dry-run` 预览**（待处理文件数、是否会触发 OCR/LLM、估计成本范围），正式执行需二次确认。`/index` 调用 **core `build_index` API**，不 shell 出去执行 CLI 字符串。二次确认通过 `PromptSession.prompt("确认执行? [y/N]: ")` 实现。

- **D-21:** REPL 主循环在 `ReplApp.run()` 内统一捕获异常，**不退出 REPL**：
  - `KeyboardInterrupt`（Ctrl+C）— 打印 "中断" 提示，继续下一轮 prompt。
  - `EOFError`（Ctrl+D）— 优雅退出 REPL，触发 postloop 持久化。
  - 任意 `Exception` from handler — 打印红色错误（`display.error(msg)`），栈追踪写入 `~/.cache/cpho/repl.log`，不退出。
  - LLM 调用失败复用 `core/llm.py` 的重试机制。

### 持久化

- **D-22:** 默认启动**仅加载 last_workspace 和用户偏好**（max_results、output_format），不自动恢复上次搜索上下文。

- **D-23:** **`/resume` 命令显式触发会话恢复**（类 Claude Code）。恢复内容：last_workspace、last_search_query、last_search_result_ids、current_problem_id、session metadata。恢复时**校验 workspace 和 index 是否仍存在**，检查 index mtime/version。如果 index 已变化，恢复 workspace 和 history，但丢弃/标记过期的 search/current_problem 上下文，提示用户重新 `/search`。

- **D-24:** **不持久化完整 IndexEntry 对象**，只持久化 problem_id 引用和轻量 metadata。`/resume` 不触发 OCR/LLM/index rebuild。`persistence.py` 用 stdlib `json` 写入 `~/.config/cpho/session.json`（XDG_CONFIG_HOME 优先）。

- **D-25:** 命令历史持久化使用 **prompt_toolkit `FileHistory`**（`~/.config/cpho/history.txt`，明文行式存储，readline 兼容）。测试时用 `InMemoryHistory` 避免污染。

### Skill 补全声明（Phase 3 预留）

- **D-26:** Phase 3 的 SkillSpec 应声明 `completions` 字段或 input type（如 `problem_ref`、`tag`、`file_path`、`enum`、`free_text`）。SkillCommandAdapter 据此生成 `Command.completer`（自定义 prompt_toolkit `Completer` 类）。Phase 02.2 定义最小接口（`Command` dataclass 字段 + `make_skill_completer(skill)` 函数签名 stub），不完整实现所有补全类型。

## Existing Code Insights

### Reusable Assets
- `core/index/api.py` 的 `query_index`/`get_problem_entry`/`find_related_problems` — REPL 命令的数据源，不重写搜索逻辑
- `core/workspace.py` 的 `discover_workspace` — workspace 验证和发现
- `core/config.py` 的配置加载 — REPL 启动时复用
- `models/index.py` 的 `IndexEntry` — `/show` 展示的数据模型

### Established Patterns
- **芯-壳分离**: REPL 在 `cli/repl/` 层，只调 `core/` API，不包含业务逻辑
- **中文 UX**: 所有用户界面默认中文
- **Pydantic 模型**: SessionState、IndexMeta 使用 dataclass（运行时可变）/ Pydantic（解析与校验场景）
- **YAML 配置驱动**: 配置通过 `config.local.yml` 控制

### Integration Points
- **Typer CLI** → REPL 是平行入口，不替换 Typer CLI
- **core index API** → REPL 查询的唯一数据源
- **core skill loader** → Phase 3 SkillCommandAdapter 的输入（Phase 02.2 预留接口）
- **Phase 3 /explain、/quiz** → 通过 `commands/builtin_skills.py` 的 `register()` 注册到 registry（Phase 02.2 预留 register() 空函数和模块占位）

## Specific Ideas

- REPL 启动 banner 格式参考 `docs/tui-repl-pattern.md` 的可视化示例（双线框、workspace + index 状态 + LLM provider）。Banner 通过 `display.banner()` 输出，使用 box-drawing 字符 + ANSI 颜色，UTF-8 终端友好（非 UTF-8 终端 fallback 到 ASCII `+-|`）。
- `/search` 结果表格格式：ID / 题目摘要 / 标签 / 来源试卷，类似 `docs/tui-repl-pattern.md` 中的示例。
- `/show` 展示格式：题目编号 + 来源文件 + OCR 文本分块 + 标签列表 + 索引日期。
- `/resume` 行为参考 Claude Code 的会话恢复——显示恢复内容摘要，校验后应用。
- `/index --dry-run` 输出类似 `cpho index --dry-run` 的统计预览。
- 输入行语法高亮（D-12）：`CphoLexer` 把命令名渲染成 ANSI Blue，`--flag` 渲染成 Yellow，普通参数 Green。这是 prompt_toolkit 相对 cmd2 的主要 UX 增益，作为 Phase 02.2 的可见亮点。
