<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Disk → session.json | Future `/resume` reads JSON from disk; malformed JSON could DoS REPL startup. |
| SessionState → session.json | We serialize last_search_query/last_search_result_ids — user input echoed back. |
| env → config_dir() | `XDG_CONFIG_HOME` env var is user-controlled; could redirect writes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.2-03 | Tampering | session.json read in `/resume` (Wave 4) | mitigate (deferred) | This plan persists data; Wave 4's `do_resume` MUST wrap `read_session` in try/except `JSONDecodeError` and fall back to fresh session. Logged as Wave 4 acceptance criterion (02.2-04). |
| T-02.2-04 | Information Disclosure | session.json content | mitigate | Payload contains only workspace path, last query string, problem_id list, and index version — no API keys, no OCR text, no config secrets (D-24). Explicit allowlist of 6 keys (see Task 3 acceptance criteria check). |
| T-02.2-05 | Tampering | XDG_CONFIG_HOME env var | accept | Local-only tool, single user (PROJECT.md). User who controls their own shell can already write anywhere; XDG override is conventional. |
| T-02.2-06 | Repudiation | history.txt | accept | FileHistory stores commands verbatim; D-25 documents this. Future enhancement: filter `/set provider <key>` style commands — explicitly out of scope for Phase 02.2 (no `/set` field accepts a key per D-10 allowed_keys). |
</threat_model>
