# TUI 模式 1：向导式交互 (Wizard/Q&A)

## 概述

类似 `npm init`、`create-next-app` 的逐步问答式交互。用户被引导完成一个线性或分支流程，每步做一个选择/输入。适合**首次使用、批量配置、标准化工作流**。

## 参考工具

| 工具 | 语言 | 核心库 | 亮点 |
|------|------|--------|------|
| `npm init` | Node | inquirer | 每步一个 prompt，默认值在括号中 |
| `create-next-app` | Node | questionary | 分支出不同的配置路径 |
| Yeoman | Node | 自研 | 可组合的 generator，每步是一个 prompt 函数 |

## Python 选型

- **questionary**: `prompt_toolkit` 的封装，提供 `text()`, `select()`, `checkbox()`, `confirm()` 等
- **Textual Screen stack**: `push_screen(StepScreen())` → `dismiss(data)` 把结果传回上屏；`push_screen_wait` 可用于 `@work` 里实现"暂停式"向导

## 优缺点

| 优点 | 缺点 |
|------|------|
| 降低认知负荷，新用户零门槛 | 高级用户会觉得繁琐 |
| 每步可做输入校验，减少错误 | 无法跳步或灵活组合 |
| 实现简单，questionary 几百行搞定 | 流程变化需要改代码逻辑 |
| 天然支持"确认摘要"防止误操作 | 不适合频繁使用的日常操作 |

## 适合 cpho 的场景

- 首次初始化配置（LLM API key、默认输出路径）
- 批量处理一个文件夹的试卷
- "处理并导出"的一次性任务

## 不适合的场景

- 日常查询某个标签下的题目
- 临时 OCR 单张图片
- 快速浏览索引
