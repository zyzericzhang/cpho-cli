## 二、模型选择与 Skill 配置面板

### 【确定设计】
- **用户自选每一步调用的 LM**：用户可以自选每一步调用什么 LM，对每个 skill 写一个面板，展示 skill 背后的每一步和步骤之间的逻辑，还有每一步提示词放在什么位置，调用哪个模型。用户运行 skill 之后展示这些，且每一步的模型也要可调整。
- **从官网实时扒取模型列表，不写死**：需要做一个官网查询，比如用户 OpenRouter 可官网查询，把支持的模型扒下来做一个选择框；其他也是一样的，比如用户是 Google AI Studio 的 API，需要从官网扒下来做模型选择。**注意不是写死，而是每次从官网扒下来。**

## 五、知识记录系统（Knowledge Base）

### 【确定设计】

#### 5.1 定位与性质
- **不是显示 skill，是共享底层**：需要一个非常重要的功能，就是知识记录，这不是一个显示 skill，却是一个类似 tag 的底层，也是共享的核心。
- **维护"知识本"**：它维护一个知识本，内容是用户对模块知识的理解——可以是私有的，也可以是社区的。
- **内容形式举例**：比如一类常考问题的方法总结，或一类模型的思路和模型描述、建模描述。

#### 5.2 社区化
- **GitHub 开源库**：希望在 GitHub 上面做一个开源库，用户可以提交上传自己在物理竞赛过程中发现的有意思的模型的总结。
- **本地使用社区智慧**：每个用户都可以从上面下载到本地，让自己的 CPHO CLI REPL 利用这些社区智慧。
- **本地私有使用**：当然用户也可以在本地写这些知识，不上传，自己用。

#### 5.3 与 Explain 的联动
- **检测 tag 对应知识文件，作为第一优先级**：利用方式是，检测到这道题目对应的 tag 有没有社区或用户自己的知识点总结，如果有，把这个作为 explain 的第一优先级参考。
- **LM 先读再写**：输出讲解时必须把这段知识总结先让 LM 阅读，再根据这个总结去写一些话，针对这个题目进行一些改写。
- **输出时标注来源**：还要输出原有知识点总结的那个位置，也就是解析必须参考对应的知识点总结。

#### 5.4 知识文件格式
- **查找方式**：查找知识点总结是查找它对应的 tag，所以写知识点总结的时候有以下规定。
- **用户不需要显式给出 tag**：用户写一份文件，里面可以是 markdown、可以是 LaTeX、可以是一份手写版的图片、可以是 word 文档，用户不需要显式给出他这个模型是关于什么的。注意这里不要给出现存 tag。
- **图片/Word 用多模态模型处理，不 OCR**：如果是 image 或者用户手写版那种图片之类的，就要做图片处理，不要 OCR，而是交给一个多模态能力比较强的模型。

#### 5.5 知识标准化 Skill（两步流程）
- **必须有一个 skill，让用户选择那个想做成标准格式知识的文件**。
- **生成标准化初稿**：然后这个 skill 可以生成一份做过 tag 标准化的符合知识文件规范的文件，存放位置放在一个临时区里。
- **两步流程**：它总是分两步——第一步是生成一个符合规范的初稿文件，让用户审核后真正放进知识区；每次都要让用户先审核。
- **用户可修改后重跑**：第一次未审核的文件也要成为完整文件，用户可以修改这份文件，直接修改，然后可以再运行一次这个 skill，再检查一次这个文件，直到用户审核通过之后才把它放进知识区里。
- **检测状态，智能处理**：如果进行下一步，就直接把已经审核过的文件存放到对应位置。注意它必须检测状态——如果已经格式正确了，一看就是经过第一轮 skill 的，只是用户想修改，就是 minimum 修改。
- **保留用户原话与原意**：如果不符合格式，还是保持用户原话，就是不管怎么样，都要尽量保持用户原话和原有意图，不要去做大幅修改，只是让它符合文件格式需求，不要改用户的原意。

## 六、Explain Skill 重新设计

> 本轮对 Explain 做了较大调整，以下内容**覆盖上一轮**的 Tone 设计。

### 【确定设计】

#### 6.1 以"板块选择"替代"Tone 选择"
- **去掉 tone 选择，改成板块选择**：explain tone 的选择去掉，改成板块选择。
- Explain 有以下可选板块，用户可按需选择：

---

**板块 1：思路描述**
- 描述一遍拿到这道题看到第一眼应该想出什么思路。
- 还有这道题之后所有处理的底层逻辑是什么，比如分析有哪些未知量，找哪些方程可以消除这些未知量，为什么要寻找这些方程。
- **这一步一定不要出完整的数学推导**。

---

**板块 2：标答替换**
- 挑出小问的关键步骤或答案没有讲全的步骤，把中间差的思路都补上。
- 尤其是答案跳步的问题，如果答案直接给出了最终结论，一定要把过程补上。
- **这不需要数学推导，且需要完整性**——就是它生成的东西要可以直接替代标准答案。

---

**板块 3：其他方法**
- 思考有没有比标准答案更好的方法或处理方式、数学处理方式。
- 比如答案用的受力法，能不能用能量法；比如标准答案是运算展开的，能不能用张量展开。

---

#### 6.2 知识文件是第一优先级（所有板块通用）
- 注意不管选了哪些板块，**如果 tag 有对应的知识讲解（知识文件），一定要先看一遍再开始 explain**，就是一定要用这些知识文件，这些是第一优先级。

#### 6.3 必须重构 Skill 架构
- 实现以上功能的时候，**一定要修改现有 skill 架构，不要妥协，不要想在现有架构下凑合**。要 jump out of the box。
