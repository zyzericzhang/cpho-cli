# TUI 模式 2：面板/仪表盘 (Dashboard/Browser)

## 概述

类似 `lazygit`、`htop`、`ncdu` 的多面板空间布局。信息按区域固定排列，用户通过键盘在面板间切换焦点，在面板内导航列表。适合**监控进度、浏览数据、频繁操作**。

## 参考工具

| 工具 | 亮点 |
|------|------|
| `lazygit` | 5 面板布局，Tab 切换焦点，`?` 弹出帮助覆盖层，50+ 快捷键但界面不拥挤 |
| `htop` | 头部仪表盘(CPU/Mem 条形图) + 可排序进程表 + 底部 F 键功能区 |
| `ncdu` | 单面板树形列表，内嵌条形图，Enter 深入 / Back 返回 |
| `k9s` | Kubernetes 管理面板，资源列表 + YAML 预览 + 日志尾部，`:` 命令模式 |

## Python 选型

- **Textual**: 唯一的现代化选择。内置 `DataTable`、`RichLog`、`Header`、`Footer`、`Static`、`ListView`。`Horizontal`/`Vertical` 容器组合面板。`set_interval(N)` 驱动实时刷新。`CommandPalette` (Ctrl+P) 提供模糊搜索命令的入口。

## 优缺点

| 优点 | 缺点 |
|------|------|
| 信息密度高，一览无余 | 实现复杂度最高 |
| Vim 式快捷键，熟练后效率极高 | 需要用户学习快捷键 |
| 内置 CommandPalette 解决功能发现 | Textual 学习曲线较陡 |
| 实时刷新天然适合监控类任务 | 终端尺寸小时布局可能挤压 |

## 如何应对"加新功能"

这是你最关心的问题。Dashboard 模式的核心策略：

1. **Command Palette (Ctrl+P)** — 每个新功能注册为一个 Command，自动出现在模糊搜索列表中，不占面板空间
2. **Footer 热键区** — 最常用的 5-6 个操作显示在底部，其余藏入 `?` 帮助层
3. **面板即插槽** — 新功能作为新面板/新 Tab，"不打扰现有布局"
4. **快捷键发现** — `?` 覆盖层自动聚合所有注册的 keybinding，新增的自动出现

> 参考 lazygit：界面只展示 5 个面板，但有 **50+ 个快捷键**。关键理念：面板承载高频操作(20%)，快捷键承载长尾功能(80%)。

## 适合 cpho 的场景

- 日常浏览题库、按标签筛选题目
- 批量处理后监控进度和重试失败
- 查看题目的切分/OCR/标签状态

## 不适合的场景

- 首次配置（用向导更快）
- 脚本化/自动化（用 CLI 直接命令）
- 编辑长文本如题目解析（用外部编辑器）
